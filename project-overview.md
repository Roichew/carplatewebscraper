# Project Overview

## What this is

A desktop app that scrapes the latest registered car plate number for every Malaysian state/area code from the JPJ (Jabatan Pengangkutan Jalan / Road Transport Department) public lookup service and exports the results to an Excel file.

- **Source page:** `https://www.jpj.gov.my/semakan-nombor-pendaftaran-terkini/`
- **Output:** an `.xlsx` file with columns `Area Code | Reg No | Date`, one row per area code in the dropdown.
- **UI:** a single Flet window (Material Design) with a save-location picker, a Start button, a progress bar, and a live activity log.
- **Packaging:** runs as `python PlateScraper.py`, or as a Windows `.exe` built via `python build.py` (PyInstaller).

## What we're getting out

The JPJ page hosts a form: pick an area code from a dropdown, type a captcha, click submit. The site responds with a JSON payload containing the latest registration number issued for that area, plus the timestamp of the lookup.

For every area code in the dropdown, we collect:

| Field     | Source                                        |
| --------- | --------------------------------------------- |
| Area Code | Dropdown option text (e.g. `WA`, `JFM`, `KV`) |
| Reg No    | `data.regno` from the submit response         |
| Date      | `data.current_time` from the submit response  |

If an area has no registrations yet, the API returns `type: "error"` and we record `regno = "Tiada Nombor Pendaftaran Terkini"` so the row still appears in the output.

## Why we can't just use `requests`

The form is protected against scripted clients by:

1. **A captcha** the user must read and type. The captcha image/text is generated by a `generate-captcha` API call and bound to the active browser session.
2. **Session/CSRF state** established when the page loads in a real browser.
3. **A locations dropdown** that's populated _after_ the page loads via `fetch(/api/locations)` — without that, you don't even know what area codes to iterate.

A plain HTTP client would have to reverse-engineer the captcha encoding, the session handshake, and the cookie/CSRF flow. Driving a real Chrome with Selenium sidesteps all of that — the page handles its own session, and we just read what's already going across the wire.

## How the data extraction trick works

Selenium drives Chrome, but **we don't read the captcha from the image and we don't parse the submit response from the DOM.** Instead:

1. Before any document loads, we use Chrome DevTools Protocol (`Page.addScriptToEvaluateOnNewDocument`) to inject a JavaScript hook (`FETCH_INTERCEPT_SCRIPT`) that monkey-patches `window.fetch`.
2. The hook watches every fetch call. When it sees:
   - A response from `…/generate-captcha` → it decodes the base64-wrapped JSON `{"data": "<plaintext>"}` and stashes the plaintext in `window.__lastCaptchaText`.
   - A response from `…/semak-no-pendaftaran-terkini` (the form submit) → it stashes the raw response body in `window.__lastResponseRaw`.
3. Python reads those globals via `driver.execute_script("return window.__lastCaptchaText")` etc., consuming them (setting them back to `null`) on read so we never reuse a stale value.

Net effect: the site generates the captcha plaintext for itself, in the page, and we just steal it out of the fetch response before passing it back into the form. No image OCR, no captcha-solving service.

The hook is re-injected automatically on every navigation (because it's registered via CDP `addScriptToEvaluateOnNewDocument`), so it survives `driver.refresh()` and any in-page navigation.

```
│ 1. App launches (Flet UI)                                          │
│    User picks an .xlsx save path → Start Scraping enabled.         │
└────────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌────────────────────────────────────────────────────────────────────┐
│ 2. start_scraping() spawns a daemon thread → scrape_data()         │
└────────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌────────────────────────────────────────────────────────────────────┐
│ 3. Launch Chrome with anti-detection flags:                        │
│      --disable-blink-features=AutomationControlled                 │
│      excludeSwitches=enable-automation                             │
│      useAutomationExtension=False                                  │
│    Inject (via CDP, on every new document):                        │
│      • navigator.webdriver = undefined                             │
│      • FETCH_INTERCEPT_SCRIPT (window.fetch monkey-patch)          │
└────────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌────────────────────────────────────────────────────────────────────┐
│ 4. driver.get(JPJ_URL)                                             │
│    Page loads → fetches captcha → fetches /api/locations.          │
│    Hook captures captcha into window.__lastCaptchaText.            │
│    wait_for_dropdown_loaded() blocks until #area_code_select       │
│    has more than the placeholder option.                           │
└────────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌────────────────────────────────────────────────────────────────────┐
│ 5. For each area code option (idx = 1 .. N):                       │
│                                                                    │
│    a. Re-fetch <select> (DOM may have been replaced).              │
│    b. Update progress bar / status / log.                          │
│    c. dropdown.select_by_index(idx)                                │
│    d. submit_and_get_data(idx, area_code) — see step 6.            │
│    e. Append row to results[] (or area_code → failed[]).           │
│    f. Every 10 rows: save_results() checkpoint to .xlsx.           │
│    g. sleep(2) to avoid hammering the server.                      │
└────────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌────────────────────────────────────────────────────────────────────┐
│ 6. submit_and_get_data — up to 3 attempts per area code:           │
│                                                                    │
│    i.   get_captcha_text() reads window.__lastCaptchaText.         │
│         If empty → reset_page_and_reselect, retry.                 │
│    ii.  Wait for #captcha input, fill it.                          │
│    iii. clear_pending_response() (null window.__lastResponseRaw)   │
│         so we don't read a stale body.                             │
│    iv.  Click #inquiry-latest-regno-submit-btn.                    │
│    v.   intercept_latest_response() polls __lastResponseRaw        │
│         for up to 5 s, then runs _parse_response().                │
│    vi.  If parsed data → return it.                                │
│         Else (captcha mismatch / no response):                     │
│           reset_page_and_reselect, sleep(1 + attempt), retry.      │
└────────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌────────────────────────────────────────────────────────────────────┐
│ 7. reset_page_and_reselect (recovery path):                        │
│      • sleep(2.5) — critical cooldown. Back-to-back refreshes      │
│        cause the locations API to fail and the dropdown shows      │
│        "gagal mendapat..." (Malay: "failed to retrieve").          │
│      • driver.refresh()                                            │
│      • wait_for_dropdown_loaded()                                  │
│      • re-select the same area_code by index                       │
│      • wait for #captcha element                                   │
│    The hook is re-injected automatically by CDP, and the page      │
│    fetches a brand new captcha — which the hook captures again.    │
└────────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌────────────────────────────────────────────────────────────────────┐
│ 8. _parse_response handles two body shapes:                        │
│      • starts with "{" → already JSON                              │
│      • else → base64-decoded JSON string                           │
│    Then by `type`:                                                 │
│      • "success" → {area_code_select, regno, current_time}         │
│      • "error"   → empty area, regno = "Tiada Nombor..."           │
│      • other     → log + return None                               │
│    `current_time` has its `\/` escapes normalized to `/`.          │
└────────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌────────────────────────────────────────────────────────────────────┐
│ 9. After the loop:                                                 │
│      • save_results(results) writes the final .xlsx via Pandas.    │
│      • Failed area codes listed in the success dialog.             │
│      • driver.quit() in finally{} ensures Chrome is closed         │
│        even on exceptions or user stop.                            │
└────────────────────────────────────────────────────────────────────┘
```

## Tunable values (all in `PlateScraper.py`)

| Value                        | Where                                            | Purpose                                               |
| ---------------------------- | ------------------------------------------------ | ----------------------------------------------------- |
| `5 s` interception timeout   | `intercept_captcha`, `intercept_latest_response` | How long to poll for the hook to populate the global. |
| `3` retries                  | `submit_and_get_data`                            | Per-area-code retry budget.                           |
| `1 + attempt s` backoff      | `submit_and_get_data`                            | Sleep between attempts (1 s, 2 s, 3 s).               |
| `2.5 s` pre-refresh cooldown | `reset_page_and_reselect`                        | Prevents `gagal mendapat...` failure mode.            |
| `2 s` inter-state delay      | `scrape_data` loop tail                          | Avoid hammering the server.                           |
| `15 s` dropdown wait         | `wait_for_dropdown_loaded`                       | Locations API can be slow.                            |
| `10` checkpoint interval     | `CHECKPOINT_EVERY`                               | Save every N successful rows.                         |

## Known failure modes & how they're handled

- **Captcha mismatch** — submit returns a non-success type. Loop refreshes the page (which produces a new captcha) and retries up to 3 times.
- **`gagal mendapat...` in dropdown** — the locations API throttles when refreshes happen too fast. Mitigated by the 2.5 s cooldown before every refresh.
- **Stale CDP request IDs** — historical, from an older performance-log approach. Eliminated by switching to the in-page `window.fetch` wrapper.
- **`Could not locate element with index N`** — historical, caused by selecting before the locations API finished. Fixed by `wait_for_dropdown_loaded()`.
